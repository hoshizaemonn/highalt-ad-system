広告自動化・CPA最適化システム
設計書（図解）

来期の通期黒字化に向けて、7店舗の広告費を「毎日自動で見える化 → AIが提案 → 承認して予算を寄せ直す」サイクルで最適化するシステムの設計を、図で示します。

1

システムの目的

Overview

現在、広告運用はB-max様に委託されており、「どの店舗に・どの広告から・1人いくらで来たか」が把握できていない状態です。全体の数字は見えても、店舗別・広告別に「止める／増やす」を判断する根拠がありません。本システムは、この“見えない”構造を解消し、広告費の無駄を日次で止めます。

機能構成（6機能）

Functions ／ 要件定義 5-1〜5-6

要件定義 REQ-2026-002 の第5章に対応する6つの機能で構成します。

FUNCTION 5-1

広告データ自動収集

Google・Meta広告の成果をAPIで毎日自動取得。キャンペーン別・広告別に日次蓄積し、CSVダウンロード作業をゼロに。

FUNCTION 5-2 ★本案件の肝

店舗別CPA見える化

「どの店舗に・どの広告から・1人いくらで来たか」を7店舗マトリクスで毎日更新。体験CPA・入会CPA・体験→入会率を店舗別に算出。店舗判定＝動線再構成（§4）

FUNCTION 5-3

日次レポート＋予算提案

毎朝、前日成果と「今日やるべき打ち手」を自動生成。CPA悪化アラート、止める候補・寄せる候補を抽出。AIは提案・実行は人の承認後

FUNCTION 5-4

動線設計アドバイス

動線の離脱ポイントを可視化し改善案を提示（LINE導線化・1枚フォーム化・Health Step活用・LP改善）。分析に基づく提案まで。

FUNCTION 5-5

AIクリエイティブ生成

勝ちパターンから広告文・画像案・動画プロンプトを自動生成。動画は Seedance（高品質・約¥1万/本）／無料簡易 の2方式。

FUNCTION 5-6 ★土台

計測基盤の整備

全広告URLへUTMを統一付与（店舗・媒体・KWを識別）。非計測流入（電話・来店・紹介）は入会時の「きっかけ」記録で補完。

4

店舗判定ロジック（本案件の肝）

Store Attribution
⚠ 課題：キャンペーン名では店舗を判定できない
現在、B-max様の運用ではキャンペーンが店舗別に切られておらず、「どの店舗に流入したか」が不明です。この特定こそが本案件の中核的な解決対象です。

解決：動線の再構成。 広告→LP→店舗ページ→体験予約の経路を、UTM・GA4・ペライチ・hacomonoのデータで突き合わせて店舗を確定します。

store / media / campaign
STEP 2

クライアントID紐付け
STEP 3

STEP 4

◆ 優先順位
① UTM（一次ソース） … 統一付与後は最も確実。 ② GA4＋ペライチの経路 … UTM欠損時の補完。 ③ キャンペーン名キーワード … あくまで補助。
非計測流入（電話・来店・紹介）は、入会時の「きっかけ」記録で運用補完します。
5

日次処理フロー

Daily Pipeline ／ 毎朝 自動実行

毎朝、以下が自動で走ります。ポイントは「AIは提案まで・実際の予算変更は担当者の承認後」という人が介在する設計です。

1
データ収集自動
Google/Meta広告APIを叩き、GA4・hacomonoのデータを取り込み。前日1日分を取得。
2
突合・店舗判定自動
UTM＋GA4＋ペライチ＋hacomonoを突合し、広告成果に店舗を紐付け（§4）。
3
CPA集計自動
店舗×媒体×広告で 体験CPA・入会CPA・体験→入会率 を算出。広告別ランキングを更新。
4
AI提案生成AI
CPA悪化を検知し「止める候補」「予算を寄せる候補」を抽出。採用時の改善効果を試算。
5
日次レポート配信AI
前日サマリ＋今日の打ち手をレポート化。ダッシュボードとレポートに反映。
6
承認 → 予算変更を実行担当者
担当者が提案を確認して承認。予算の寄せ直し・配信停止を実行（御社は提案を見て選ぶだけ）。
6

データモデル

Data Model ／ ad_performance

中核テーブル ad_performance に、店舗×媒体×キャンペーン×広告の日次成果を一元管理します（実装済みスキーマ）。

カラム型内容
dateTEXT日付（YYYY-MM-DD）
mediaTEXT媒体（meta ／ google）
storeTEXT店舗名 ／「未判定」（§4で判定）
campaign_nameTEXTキャンペーン名
adset_name / ad_nameTEXT広告セット名 ／ 広告名
impressions / clicksINTEGER表示回数 ／ クリック数
spendREAL広告費（円）
conversionsREAL媒体側CV（体験申込 等）
lp_viewsINTEGERLP到達数（動線分析用）

※ 体験CPA・入会CPA・体験→入会率は、この表と hacomono 実売データの突合から算出します。ユニークキー (date, media, campaign, adset, ad) で日次UPSERT（重複なし）。

7

既存PLダッシュボードとの統合

Integration ／ 要件定義 6章

既に運用中の PL管理ダッシュボード（7店舗・Next.js） に広告サマリを接続。広告費 → 体験・入会 → 店舗別PL（販促費）→ 黒字化まで一気通貫で追えます。広告レポートだけを納品する会社との最大の違いです。

広告投資 → 最終PL（黒字化）まで一気通貫
LAYER 1
広告費
媒体別・店舗別に自動取得（本システム）
LAYER 2
体験 → 入会
hacomonoと自動突合
LAYER 3
店舗別PL（販促費）
既存ダッシュボードに反映
LAYER 4
通期黒字化
広告効率→PLの効きを毎月確認
◆ 統合方式
収集〜集計は媒体非依存で実装済み（Python＋SQLite）。既存ダッシュボードへの表示統合方式（Next.js側に取り込む／専用画面を追加）は、現状分析を踏まえ最小工数の形で確定します。
